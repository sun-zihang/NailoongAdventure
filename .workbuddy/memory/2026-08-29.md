## 线上打不开游戏的根因与修复（补充：下午）

### 根因（关键！）
- **Cloudflare Pages 单文件硬上限 25MB**。之前 `GameBuilder.cs` 设 `WebGLCompressionFormat.Disabled`，wasm=42MB、data=18MB 均超限，被 Cloudflare **静默丢弃成 0 字节/404 兜底页** → 线上 `/game/Build/*` 全是空文件，游戏无法加载。
- 之前误判为「GitHub 自动构建失败/路径错」，实际构建正常，只是大文件被吞。

### 修复（commit cc0c928，已推送 + Wrangler 直部署）
- `GameBuilder.cs`：`Disabled` → **`Brotli`**。wasm 42MB→**7.6MB**、data 18MB→**8.8MB**，全部 <25MB。Unity 6 loader 在 JS 端用 CompressionStream 自动解压，无需服务端 Content-Encoding。
- 重建 WebGL 后覆盖 `WebGLBuild/`（清掉旧的未压缩文件，只留 `.br` 压缩版）。
- **直部署用 Wrangler**（用户给了 API Token + Account ID）：设 `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`，命令 `node_modules/.bin/wrangler pages deploy dist --project-name nailoongadventure`（token 需 Pages:Edit 权限）。Wrangler 装在隔离 node 工作区 `C:/Users/33352/.workbuddy/binaries/node/workspace`。
- 已推送 `main`，GitHub 自动构建也跟随产出压缩版，双路一致。

### 验证要点（避坑）
- `.br`/`.gz` 文件 Cloudflare **仅在客户端请求带 `Accept-Encoding: br` 时才返回完整内容**；curl 不带该头会显示 0 字节/Content-Length 缺失——这是 Cloudflare 对预压缩扩展名的标准行为，**真实浏览器 fetch 会自动带该头，正常拿到文件**，不是部署故障。

## 第二轮修复：Brotli 仍报 Unable to load file + 鼠标不可见（晚，commit 3d73da1）

### 根因（比第一轮更隐蔽）
- 第一轮只用 `compressionFormat=Brotli`，产物是 `.br` 文件。Cloudflare Pages **对 `.br` 文件不返回 `Content-Encoding: br` 响应头**（只给 `application/octet-stream`）。而 Unity 6 默认关闭 Decompression Fallback 的 Brotli 构建，**依赖浏览器靠 `Content-Encoding: br` 自动解压**——拿不到头，浏览器把压缩字节当 JS 执行 → 报 `Unable to load file Build/WebGL.framework.js.br`。
- **Unity 官方正解**：开启 `PlayerSettings.WebGL.decompressionFallback = true`。开启后 Unity 把 JS 解压器嵌进 loader，自己解压 `.unityweb` 文件，**完全不依赖服务器响应头**。这正是「无法配置服务器 Content-Encoding」的托管（Cloudflare Pages / GitHub Pages）的标准做法。产物扩展名由 `.br` 变 `.unityweb`。
- **鼠标不可见根因**：`CameraRig.Start()` / `GameManager.Resume` / `UIPanels` 在运行时强制 `Cursor.lockState=Locked; Cursor.visible=false`。WebGL 上 pointer lock 需用户手势，结果光标被隐藏又没真锁定 → 看不到鼠标。

### 修复（commit 3d73da1，已推送 + Wrangler 直部署）
- `GameBuilder.cs`：`compressionFormat=Brotli` + `decompressionFallback=true`；移除之前注释里「依赖服务端 Content-Encoding」的误导说明。重新构建（19:23，0 错误）产物全为 `.unityweb`。
- 三处光标逻辑加 `#if UNITY_WEBGL` 分支：WebGL 保持鼠标可见、不锁指针；桌面端保持原锁定转视角。
- 重建 `dist/`（务必先 `rm -rf dist` 清掉旧 `.br`，否则 `build-site.js` 的 copyDir 会合并残留旧文件把上传撑到 32MB）。
- Wrangler 部署成功 → 生产 `https://nailoongadventure.pages.dev/game/`，新预览 `https://313167fc.nailoongadventure.pages.dev`。
- 线上 `Content-Length` 与本地源文件字节数完全一致（wasm 7628774 / framework 78517 / data 8841383），证实 `.unityweb` 被完整托管（Cloudflare 对 `.unityweb` 不像 `.br` 那样特殊处理）。

### 关键经验（务必记住，下次别再踩）
- **在 Cloudflare Pages / GitHub Pages 部署 Unity WebGL，必须开 `decompressionFallback = true`**（或服务器能正确返回 Content-Encoding）。单纯 Brotli 压缩而不开 fallback，在无法配置响应头的静态托管上必现 `Unable to load file`。
- `.unityweb` 扩展名是 fallback 模式的标志，比 `.br` 更稳，因为不依赖服务器头。

## 第三轮：音频解码报错仍未根治 → 改为运行时合成（commit 11a916a）

### 音频问题的最终解法
- 第二轮改 Vorbis 导入后仍报 `Unable to decode audio data` + 新增 `Unknown data format (id='')`。
- 根因：Unity WebGL 把 Resources 里的音频字节交给浏览器 `decodeAudioData`，部分浏览器（移动端/微信内置）对压缩音频解码不稳定。**改导入格式治标不治本**。
- **正解：WebGL 上完全绕过 `Resources.Load<AudioClip>`，全部用 `AudioClip.Create` 运行时合成**。运行时创建的 clip 不经过浏览器解码，100% 可靠。
- 实现：`AudioManager.GetClip()` 加 `#if UNITY_WEBGL` 分支，WebGL 走 `SynthClip() ?? SynthMusic() ?? 默认音`；桌面端仍先 `Resources.Load` 再回退。
- 新增运行时 BGM 合成器 `SynthMusicLoop()`（和弦铺底 + 旋律 + 鼓点，8 拍循环）与 `SynthRoar()`（Boss 咆哮），覆盖 bgm_menu/level1~3/boss/victory。
- 注意：`SynthClip` 的 `default` 分支必须返回 null，否则 `?? SynthMusic()` 永远不会被调用。

### 建模重做（对齐官方设定）
- 查证官方设定（第七印象 nailoong.com + 百科）：**奶黄色、圆大脑袋、duang~duang Q弹大肚腩、大圆眼、无耳朵、小爪爪、短尾巴**；技能喷火/变色/变大变小。

## 第四轮：wasm 编译报错 + 热路径性能优化（commit 979764f / ec5575f）

### 又一个坑：CDN 自动压缩破坏 .unityweb
- 报错：`WebAssembly compilation error: "Content-Encoding" header is incorrectly enabled ... both async and sync fetching of the wasm failed`。
- 根因：Unity Decompression Fallback 期望拿到**原始 .unityweb 字节**由 JS 端自行解压。若 CDN（Cloudflare）对其自动 Brotli 压缩并附加 `Content-Encoding: br`，浏览器透明解压后交给 Unity 的字节就不对了 → loader 校验失败。
- **修复：`_headers` 里为 `.unityweb` 加 `Cache-Control: no-transform`**，禁止 CDN/代理转码。同时把缓存缩到 300s，避免浏览器拿到旧的错误缓存响应。
- 验证：`curl -I` 看 `.unityweb` 应**无 Content-Encoding**；而 `loader.js` 仍被自动 Brotli 压缩（`Content-Encoding: br`）是正常的——浏览器会透明解压。
- 注意：本沙箱 curl 有时看不到 Content-Encoding（不同出口/区域表现不同），**用户浏览器看到的才是真实情况**，不能只凭本地 curl 判断。

### 热路径性能优化（WebGL 移动端收益明显）
- `PlayerCombat.TickTimers()`：每帧 `new List<string>(Cooldowns.Keys)` → 复用 `List` 缓冲。
- `PlayerCombat.ConeHit()`：`Physics.OverlapSphere`（每次分配数组，冲撞时每帧调用）→ `OverlapSphereNonAlloc` + 复用 `Collider[64]`。
- 移除 `KnockbackFeel` 空协程（只 `WaitForSeconds` 不做任何事，纯分配）。
- `DragonAnimator.IndexOf()`：逐帧线性扫描字符串 → 静态 `Dictionary<string,int>` 查表（`Add()` 每帧调用数十次）。
- `EnemyController` / `BossController.Animate()`：每帧 `transform.Find("Wing_L"/"Wing_R"/"Tail1")` → `Awake` 时缓存 `Transform` 引用。

### 构建耗时参考
- `BuildAll` ≈ 10~11s（资产已缓存时）；WebGL 首次 ≈ 19min，增量 ≈ 5~7min。
